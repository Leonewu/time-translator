# Time Translator 大众版 Roadmap

状态：公开版分支实施中（2026-09-30），尚未上架。本文记录已讨论的取舍与实施顺序。竞品依据见 [竞品与替代品研究](./market-research.md)。

当前进展：第 1–3 阶段的扩展代码、双语元数据与隐私说明已在 `feat/public-time-translator` 实现并通过本地测试与模拟模型响应的界面检查；尚未进行真实服务商端到端验收或商店发布。第 4 阶段的人工金标准语料、竞品盲测与正确率评估仍待开展，因此不要把它们视为已验证的产品宣称。

## 产品定位与已决定的边界

Time Translator 是一款 **BYOK 的高级时间表达理解工具**：用户选中网页或邮件中的英文时间表达，由自己配置的模型服务商理解语义，插件在本地按 IANA 时区规则换算。差异点是理解截止、时间范围和 Gmail 邮件日期上下文，而非制作另一个世界时钟或会议排期工具。

- **API Key 是正式转换的前提**。不做“简单格式免 Key、复杂格式再用 AI”的分流，也不暗示插件会替用户判断何时需要模型。没有 Key 时明确提示配置，不静默改用本地解析。
- **不增加首次启动流程**。继续使用现有 Popup 配置面板和在线测试；用户打开配置面板后，自行选服务商并配置。
- **Magic Code 保留**。当代码为 `emma` 时可显示 Emma 专属图标、文案和彩蛋；其他用户不应看到私人祝福或带空名字的私人文案。它是客户端彩蛋开关，不是安全认证或付费权限。普通用户的文案和节日内容应中性、可本地化。
- **界面语言、输入语言、目标时区是三件事**。第一轮面向非中文用户时，先完成英文界面与英文结果展示；正式支持的自然语言输入仍为英文，标准数字格式按现有合同处理。不因界面翻译就宣传支持任意语言输入。
- **BYOK 数据边界不变**：用户的 Key 留在本机扩展存储；选中文字在触发解析时发送给所选服务商；Gmail 相对日期所需的邮件时间可能一同发送，不发送整封邮件。对自动检测触发时的数据流也要说清楚。

## 实施顺序

### 1. 隔离定制内容与公开发布检查

将 VIP 标志以外仍面向所有人展示的 Emma 私人文案、普通彩蛋中的姓名替换和长按祝福纳入 `emma` 判断；普通用户保留适当的中性体验，而不是删除 Emma 体验。检查节日自动效果是否在普通用户的转换流程里造成干扰。核对反馈上报的数据内容与隐私说明；处理客户端内置的反馈 webhook，避免公开分发时把可调用的地址当作秘密。

**完成标志**：无 Magic Code、任意非 `emma` 代码和 `emma` 三种状态分别检查；前两者看不到私人内容，后者保留专属体验。反馈发送路径、用户主动操作和公开说明一致。

### 2. 国际化与时区语义一致性

新用户的目标时区使用浏览器时区，已有用户已保存的目标时区不被覆盖。Popup、Tooltip、右键菜单、结果日期和星期、关系词、错误提示、复制按钮及相关说明采用一致的中英语言；显示的目标时区必须与实际换算时区一致，不再一律写“北京时间”。源时区未写明时，结果明确展示所采用的假设；默认伦敦不应被包装成原文已说明的事实。对外文案清晰写明“英文自然语言输入”，不承诺尚未验证的中文、日文自然语言解析。

**完成标志**：在英文浏览器环境、非上海目标时区下，完成一次正常、一次失败和一次 Gmail 相对日期转换，均无中文残留或时区误标；中文环境及已有设置也正常。

### 3. 在现有 Provider 配置旁提供获取 Key 的入口

在 Popup 的 Provider 选择区域下方，随所选服务商显示一条可点击的 **“前往获取 API Key”** 链接，打开该服务商经核实的官方申请或控制台页面。用户返回后仍在原有输入框粘贴 Key、选择模型并运行在线测试；不新增向导、弹窗或账户系统。自定义 Endpoint 没有统一申请入口时不展示误导性链接。链接不携带 Key、选中文字或其他个人数据，不宣称未谈妥的合作权益；日后若有小米等服务商的合作链接，可在披露关系后更新对应入口。

**完成标志**：切换服务商时链接同步变化、指向正确的一方页面；无有效官方入口时不伪造链接；中英文文案可用，返回配置面板不丢失未提交输入，现有测试流程不变。

### 4. 验证差异化，再决定扩展范围

使用有人工金标准的语料评估 `before/by/after/between`、相对日期、夏令时边界、未写时区和 Gmail 邮件时间上下文；与选中式及自动式竞品作同场景对照。记录端到端正确率、错误假设、失败原因、延迟，以及用户能否识别并纠正模型的理解。对外只宣传经验证的能力。

**决策点**：若复杂英文表达与 Gmail 上下文的收益确实成立，再确定后续输入语言的优先级与所需评测；不因做了中英界面就立即承诺多语言自然语言支持。

## 当前不做

- 免 Key 的转换模式、规则与模型的自动分流、托管模型或自建中转服务。
- 首次打开先选 Provider、分步骤配置向导、账户/付费体系。
- 未经验证的多语言自然语言输入承诺，或会议规划、多人排期、整页自动改写。
- 在未达成协议前把普通官方链接描述为小米或其他服务商的合作推广。

实施时以现有行为和测试为准；本文件是范围与验收依据，不要求一次性完成所有阶段。

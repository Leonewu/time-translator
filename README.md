# Time Translator

> 元气100%的时区转换工具
>
> 把一句英文里的当地时间，换算成一眼能懂的北京时间。

Time Translator 是一个 Chrome / Edge Manifest V3 浏览器插件。选中网页中的时间表达，插件负责理解原文、识别时区，再把结果转换成普通人容易读懂的日期和时间。

## 产品功能

### 一句话看懂时差

选中 `today before 3 pm UK` 这样的表达，就能看到对应的北京时间，例如：

`2026/08/20（周四）22:00 前`

### 自动检测，也能手动触发

- **自动模式**：选中文本并释放鼠标后，只有通过本地候选检查的内容才会发起解析。
- **手动模式**：关闭自动检测后，选中文本，右键点击“检测并转换时间”即可。
- **自定义触发词**：可添加业务术语、项目缩写或短语；匹配不区分大小写。

### Gmail 邮件上下文

在 Gmail 网页版中，选中文字所属邮件的时间会作为相对日期参考。邮件是昨天收到的时，`today 12:00 UK` 会按那封邮件当天的 `today` 解析，而不是按当前日期解析。只发送选中文字和必要的邮件时间，不发送整封邮件。

### 识别常见时间表达

支持 `today`、`tomorrow`、`next Monday`，12/24 小时制，以及 `before`、`by`、`after`、`between` 等截止时间和时间范围表达。

同时支持带数字时区偏移的标准格式，例如 `2026-08-20 15:00 UTC+01:00`、ISO 8601 和 RFC 3339 风格的时间。

### 夏令时，交给时区规则处理

模型只负责理解英文语义；真正的时间换算由插件在本地完成，并使用 IANA 时区规则处理夏令时、冬令时、跨日和非整小时偏移。

### 模型由你选择

支持 DeepSeek、小米 MiMo、通义千问、智谱 GLM、Kimi、豆包、Google Gemini、OpenRouter，以及其他 OpenAI-compatible 接口。

填写 API Key 后，可以从服务商动态刷新可用模型；如果服务商不提供模型列表，也可以手动填写模型名。在线测试与模型配置放在同一个 Popup 内，配置完成即可验证。

### 简洁的 Popup 配置

日间/夜间模式、API Key 显示/隐藏、自动保存、目标时区、自定义触发词和在线测试，都集中在扩展 Popup 中完成。

VIP 用户输入 `emma` 后，Popup Logo 和浏览器工具栏图标会实时切换为 VIP 版本。Tooltip 中的“接案順心!”按钮还藏有一个彩蛋：连续点击时 Tooltip 会进入半透明状态，并在停止点击约 3 秒后缓慢恢复；每次完成 10 秒内点击 10 次都会喷出爱心，文案按 `🧩 emma~`、`Stay lovely!`、`Be happy!`、`Stay cozy!`、`Be carefree!` 循环。长按超过 1 秒会让按钮倾斜颤抖，松手后使用普通蓄力彩带并显示紫色 `🧩 emma~`。

### 隐私优先

只向你选择的模型服务商发送主动选中的文本；在 Gmail 网页版中，还可能发送选中文字所属邮件的时间，用于理解 `today`、`yesterday` 等相对日期。不发送整页或整封邮件。API Key 和个人偏好保存在本机浏览器扩展存储中，项目本身不经过自建中转服务器。

## 当前支持的检测语言

### 正式支持：英文

当前的自然语言解析合同、候选词检查和本地解析器，都是围绕英文时间表达设计和测试的。正式支持的例子包括：

- `today before 3 pm UK`
- `tomorrow at 9:30 AM New York`
- `next Monday between 10 and 11 am`
- `by 18:00 London time`

### 与语言无关：标准数字格式

带完整日期、时间和数字时区偏移的格式，不依赖自然语言，例如：

- `2026-08-20 15:00 UTC+01:00`
- `2026/08/20T15:00:00Z`
- `2026-08-20 15:00 +0800`

### 暂不承诺：其他自然语言

中文、日文、韩文等自然语言时间表达目前没有纳入正式支持范围。自定义触发词可以让非英文文本进入检测流程，但这只解决“是否尝试检测”，不代表模型解析结果已经稳定可靠。

## 配置在线模型

点击扩展图标，在 Popup 内选择服务商、填写 API Key；模型名可以手动填写，也可以点击旁边的刷新按钮从服务商动态读取。输入和选项会自动保存。

在线模型 Endpoint 必须使用 HTTPS。选中文本只在发起转换时发送到用户选择的模型服务商，不发送整页内容。刷新模型列表时，会向当前 Endpoint 推导出的 `/models` 地址发送带 API Key 的请求，不会发送选中的网页文本。

隐私政策见 [`privacy-policy.html`](./privacy-policy.html)。

API Key、自动检测开关和自定义触发词使用 `chrome.storage.local` 保存。开启自动检测时，在线模型只接收通过本地时间候选检查的用户选中文本；关闭自动检测后，只有右键菜单会发起检测。没有 API Key 或在线请求失败时，会显示明确原因。

自定义触发词在 Popup 的“转换偏好”中每行填写一个，也支持逗号或分号分隔；空格会保留为短语，匹配不区分大小写，最多保存 30 个、每个不超过 60 个字符。命中后仍需完成鼠标选择并释放，才会发起解析。

流程是“本地候选检查 → LLM 输出规范化当地时间 JSON → 本地 IANA 时区规则换算”。LLM 会根据插件传入的参考时刻解析 `today` 等相对日期，但不直接计算北京时间。

在线模型的 `source_time_zone` 只接受规范化 IANA 时区标识，例如 `Europe/London`、`America/New_York`、`Asia/Shanghai`、`UTC`。插件会统一大小写并将少量 IANA 别名归一化；`CST`、`BST`、`UTC+08:00` 等缩写或固定偏移不会放进这个字段。固定偏移直接从原文中由插件提取并解析成内部分钟数，LLM 不参与这一步；原文包含固定偏移时，也不允许模型返回 IANA 时区。

火山方舟需要把模型名替换成你自己的 Endpoint ID；阿里云百炼也可以使用业务空间专属 Endpoint。

## 测试边界

本项目的核心测试 seam 是：

- `parseEnglishTimeExpression()`：英文表达解析
- `parseStructuredTimeExpression()`：LLM 结构化结果解析
- `resolveLocalDateTime()` / `formatBeijingDateTime()`：IANA 时区转换和普通中文展示
- `requestOpenAICompatibleExtraction()`：兼容接口适配

时间转换最终由程序和 IANA 时区数据库完成，LLM 只负责理解英文语义。
